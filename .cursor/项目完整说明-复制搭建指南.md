> **本文档用途**：复制本项目搭建另一套独立环境时，交给 AI 或运维人员阅读的主说明文档。  
> **最后更新**：2026-05  
> **项目类型**：uni-app 微信小程序 + uniCloud（阿里云）车辆装卸排队管理系统

---

## 一、项目概述

本系统用于仓库/物流场地的**车辆装卸排队管理**，主要功能：

- 司机微信登录后排号、查看进度、上传完成照片
- 管理员查看处理中/排队中/已完成列表，代完成、取消、插队开始处理
- 微信订阅消息通知（到号、进度、排队成功）
- 公告管理（含首页弹窗公告）
- 系统配置（用户协议、隐私政策、操作指引、排队开关）
- 管理员增删、Excel 导出

**两个 Tab 页**：
- 首页（装卸）：排队列表、我要排队/修改信息、装卸完成
- 我的：登录、管理员功能、操作指引、联系客服

## 八、核心业务逻辑（排队流程）

### 8.1 订单状态流转

```
用户提交 register
    ↓
若当前无处理中订单 → status=1 处理中（admin_started=false）
否则               → status=0 排队中
    ↓
用户 complete（需 status=1，上传完成照）→ status=2 已完成
管理员 adminComplete（需 status=1，不需照片）→ status=2 已完成
    ↓
【仅正常流程处理中单】完成/取消后 → 自动将队首排队中升为处理中 + 发通知

用户 cancelTask（排队中或处理中）
    ↓
status=3 已取消
    ↓
【仅正常流程处理中单】取消后 → 自动升下一个
```

### 8.2 管理员插队（多处理中并行）

管理员在 **排队中订单详情** 点击 **「开始处理」**：

- 调用 `truck.adminStartProcessing`
- `status: 0 → 1`
- `admin_started: true`（标记为插队单）
- **不改变 queue_number**
- 给用户发「请就位」订阅消息
- 可与正常流程的处理中订单**同时存在多个**

**插队单完成/取消后**：
- **不会**自动把下一个排队中升为处理中
- **不会**触发排队进度通知补位逻辑

**正常流程处理中单**（`admin_started !== true`）完成/取消后：
- **会**自动升队首排队中为处理中（`admin_started: false`）
- **会**通知排队中前 3 名进度变化

### 8.3 前端限制

| 场景 | 规则 |
|------|------|
| 处理中 | 不可修改信息、不可用户取消 |
| 排队中 | 可修改、可用户取消 |
| 首页「修改信息」 | 处理中点击提示不可修改 |
| 提交排队 | 需勾选协议；检查 `queue_switch`；车牌号去空格后校验格式 |
| 完成 | 仅 status=1 可提交（前后端双重校验） |

### 8.4 预计等待时间（首页）

根据前方排队列表中各车型估算：
- 依维柯：10 分钟
- 3.8/4.2/7.6/9.6 米：30 分钟
- 13.5/17.5 米及以上：60 分钟

## 九、微信订阅消息逻辑

云函数 `truck/index.obj.js` 使用 `uniCloud.httpclient.request` 调用微信 API。

**重要实现细节**：
- 在 `register` / `complete` / `adminComplete` 开头**预热** `access_token`，避免冷启动超时
- 发送订阅消息必须 **同步 await**，不可用异步 IIFE
- `phrase` 字段不能含标点，如「请就位」而非「轮到您了，请就位」

| 场景 | 模板 | 条件 |
|------|------|------|
| 登记后直接处理中 | 排队到号 | 无其他处理中 |
| 登记后排队，位置 ≤3 | 排队进度 | 前面人数 |
| 登记后排队，位置 >3 | 排队成功 | 前面人数 + thing 文案 |
| 正常流程完成后升下一个 | 排队到号 | 下一用户 |
| 管理员开始处理（插队） | 排队到号 | 被插队用户 |

**注意**：微信订阅消息为一次性订阅，用户每次授权仅 1 次发送额度。无长期订阅能力。

**网络**：阿里云 uniCloud 访问微信 API 可能需配置 EIP 或关闭微信 IP 白名单，详见 `.cursor/云函数网络问题排查.md`

## 十四、常见问题

| 问题 | 原因/处理 |
|------|-----------|
| 订阅消息 47003 参数 invalid | 车牌号格式不对；phrase 含标点或超长 |
| 订阅消息超时 | 云函数冷启动，已在 register/complete 预热 token；检查阿里云出网 |

## 十六、给 AI 的关键约束摘要

1. **不要**假设 `uni-id-roles` 表控制权限，实际看 `uni-id-users.role`
2. **不要**在插队单（`admin_started=true`）完成/取消时自动升下一个
3. **不要**改回 `uni.showLoading`，统一用 `utils/loading.ts`
4. **不要**在订阅消息 phrase/thing 里加中文标点
5. 车牌号提交前必须去空格并校验：`/^[\u4e00-\u9fa5][A-Z][A-HJ-NP-Z0-9]{4,6}$/`
6. 复制新项目必须换：AppID、AppSecret、uniCloud 空间、订阅模板 ID
7. `opendb-city-china` 和 `system_info` 初始数据是跑通业务的必要条件
